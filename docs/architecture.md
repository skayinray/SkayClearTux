# Архитектура SkayClearTux

Документ для тех, кто хочет понять устройство проекта или добавить в него экран
или функцию. Пользовательская документация — в [README.md](../README.md).

## Слои

Проект разделён на три слоя. Каждый следующий не знает о существовании
предыдущего — зависимости идут строго в одну сторону.

```
┌──────────────────────────────────────────────────────────────┐
│  Интерфейс (Qt/PySide6)                                       │
│  main_window.py · pages.py · extra_pages.py · tools_pages.py  │
│  settings_page.py · chess_widget.py · palette.py             │
└───────────────────────────┬──────────────────────────────────┘
                            │ вызывает функции по именам
┌───────────────────────────▼──────────────────────────────────┐
│  Фасад  system_tools.py                                       │
│  один и тот же API для всех ОС; сам выбирает бэкенд           │
└───────────────────────────┬──────────────────────────────────┘
                            │ BACKEND = get_backend()
┌───────────────────────────▼──────────────────────────────────┐
│  Бэкенды  skaycleartux/backends/                              │
│  base.py (контракт + заглушки) → linux.py / macos.py /        │
│  windows.py → common.py (запуск команд, права, пути)          │
└──────────────────────────────────────────────────────────────┘
```

- **Интерфейс** не вызывает `subprocess` и не знает про конкретную ОС. Он
  дёргает `system_tools` (`st.list_processes()`, `st.disk_usage()` и т. п.).
- **`system_tools.py`** — тонкий фасад. Держит единственный экземпляр бэкенда
  (`BACKEND = get_backend()`), повторяет его методы и хранит пару утилит
  (заметки, `dir_size_str`, `run_rsync`). Часть имён реэкспортируется из
  `backends.common` для обратной совместимости.
- **`backends/`** — кроссплатформенное ядро. `get_backend()` по
  `common.FAMILY` выбирает реализацию под текущую ОС. Всё, что не
  переопределено, берётся из `BaseBackend` и возвращает безопасную заглушку.

## Запуск

```
SkayClearTux.py            → тонкая обёртка (для PyInstaller)
skaycleartux/__main__.py   → создаёт QApplication, MainWindow, трей
skaycleartux/main_window.py→ MainWindow
```

## Главное окно

- `NAV` — список разделов и экранов (ключ → подпись). Порядок `NAV` задаёт
  порядок страниц в стеке.
- `MainWindow._create_pages()` — словарь `key → экземпляр виджета`.
- `MainWindow.key_index` / `index_key` — соответствие ключа и индекса в стеке.
- `FadeStack` — `QStackedWidget` с кроссфейдом при переключении.
- `_goto(key)` — переход на страницу, `_cycle_page(±1)` — листание, `Ctrl+K`
  открывает палитру команд (`palette.py`).
- Трей создаётся только если `QSystemTrayIcon.isSystemTrayAvailable()`.

## Настройки, темы, обновления

- **`settings.py`** — обёртка над `QSettings` со словарём `DEFAULTS`. Все
  ключи читаются через `settings.get("ключ")`.
- **`themes.py`** — `THEMES` (7 тем), `build_qss(colors)` генерирует QSS.
  `MainWindow.apply_theme(name)` применяет тему ко всему приложению.
- **`updater.py`** — см. раздел «Обновления» ниже.
- **Логирование** — ошибки бэкендов пишутся в файл лога в стандартном каталоге
  ОС (см. `SECURITY.md`).

## Обновления (`updater.py`)

Дистанционные обновления работают по статическому JSON-манифесту:

```json
{
  "version": "1.3.0",
  "url": "https://github.com/.../SkayClearTux-1.3.0-x86_64.AppImage",
  "sha256": "…",
  "notes": "Что нового",
  "published": "2026-11-16"
}
```

Алгоритм:

1. `fetch_manifest(url)` — читает манифест **только по HTTPS**.
2. `is_newer(remote, current)` — сравнивает версии по числам.
3. `download(url, dest, sha256)` — качает файл во временный каталог, считая
   SHA-256 на лету; при несовпадении файл удаляется и установка прерывается.
4. `install_appimage(downloaded, target)` — атомарно подменяет текущий
   AppImage (`os.replace`, при разных ФС — копия рядом и подмена).
5. `restart(target)` — запускает новую копию отдельным процессом.

`safe_filename()` отбрасывает каталоги и `..`, чтобы имя из манифеста не
превратилось в путь вне каталога загрузок. Подробнее о мерах — в
[SECURITY.md](../SECURITY.md).

## Как добавить экран

1. Напишите виджет страницы (например в `extra_pages.py`), наследуя `QWidget`.
   Если у страницы есть метод `refresh()` — он вызывается при `Ctrl+R` и
   переключении.
2. Добавьте ключ и подпись в `NAV` (`main_window.py`) в нужный раздел.
3. Зарегистрируйте экземпляр в `_create_pages()` под тем же ключом.
4. Добавьте описание раздела в `helptext.py` (для подсказок и Справки).
5. Обновите число экранов в `README.md` и `CHANGELOG.md`.

Проверьте: `QT_QPA_PLATFORM=offscreen python tools/smoke_test.py` — он сверит
число страниц с `NAV` и поищет «квадратные» глифы.

## Как добавить функцию бэкенда

1. Добавьте метод-заглушку в `BaseBackend` (`backends/base.py`) — что вернуть,
   если функция недоступна.
2. Переопределите метод в `linux.py` / `macos.py` / `windows.py`, где это
   имеет смысл. Команды запускайте через `common.run(...)` списком аргументов,
   без `shell=True`, с таймаутом.
3. Пробросьте метод в `system_tools.py`.
4. Вызовите его из страницы интерфейса и корректно обработайте «недоступно».
5. Добавьте тесты (см. ниже) и обновите `docs/backends.md`, если контракт
   расширился.

Подробнее о контракте — в [docs/backends.md](backends.md).

## Безопасные заглушки

Принцип: **отсутствие функции не должно ронять программу**. Для этого
`BaseBackend` возвращает нейтральные значения, а не бросает исключения:

- `list_*()` → `[]`;
- `*_info()` → пустая строка/`{}`/нули;
- действия (`kill_process`, `install_packages`, `service_action`) →
  `(False, NOT_AVAILABLE)`;
- `bool`-действия → `False`.

Интерфейс показывает такие ответы как «недоступно» и не считает их ошибкой.

## Тесты и проверки

- `tests/` — юнит-тесты бэкендов, `cleaner.py`, `system_tools.py`, `updater.py`
  и UI-тесты на pytest-qt. Запуск: `python -m pytest -q`.
- `tools/smoke_test.py` — поднимает интерфейс в offscreen, обходит страницы,
  проверяет бэкенд и глифы.
- `tools/pkg_check.py` — самопроверка менеджеров пакетов Linux.
- `python -m ruff check skaycleartux tests tools` — линтер (блокирует CI).
- `black` и `mypy` — в мягком режиме (не блокируют сборку).

## Стиль кода

- Python 3.11+, длина строки до 100 символов, текст интерфейса — на русском.
- Без эмодзи и редких стрелок/знаков — Qt рисует их пустыми квадратами.
  Разрешены `– — … • · ± × ° « »`.
- Системный код — только через `backends/`, без `shell=True`.
